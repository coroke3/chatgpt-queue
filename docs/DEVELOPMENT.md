# 開発ガイド

この拡張機能は、ChromeのManifest V3で動作します。JavaScript・HTML・CSSを直接読み込むため、ビルド工程はありません。

## セットアップ

Node.jsとnpmを用意し、リポジトリのルートで依存パッケージをインストールしてください。Node.jsは、組み込みのテストランナーと依存パッケージの実行要件を満たすバージョンを使います。

```sh
npm ci
npm run check
npm test
```

PowerShellでは `npm.cmd ci`、`npm.cmd run check`、`npm.cmd test` も使えます。拡張機能の読み込み方法は[README](../README.md#導入方法)を参照してください。

## ファイル構成

| ファイル・フォルダ | 役割 |
| --- | --- |
| `manifest.json` | 権限、対象URL、読み込むスクリプト、バージョン |
| `content.js` | タブ・会話ごとのキュー、入力・送信処理、ページ内パネル |
| `queue-timing.js` | 非表示タブのキュー処理をサービスワーカー側のタイマーで待機 |
| `model-picker.js` | サービス側のモデル・思考設定の取得と選択 |
| `composer-tools.js` / `.css` | アプリ・ツールの指定、入力補助、選択状態の確認 |
| `references.js` | 引用元の抽出と参照カードの表示 |
| `snapshot.js` | 回答の表示構造の取得と管理画面への受け渡し |
| `styles.css` | 対象ページに追加するUIのスタイル |
| `dashboard.html` / `.js` / `.css` | Queue Managerの表示とタブの遠隔操作 |
| `scrollbars.js` | 管理画面のスクロールバーの重ね表示とドラッグ操作 |
| `background.js` | 拡張機能のサービスワーカー、タブ・管理画面の連携 |
| `popup.html` / `.js` | ツールバーポップアップ |
| `libs/` | Markdown・Mermaid表示用のライブラリ |
| `icons/` / `generate_icons.py` | アイコンと生成スクリプト |
| `tests/` | Node.jsのテストランナーとJSDOMによる自動テスト |

## 自動テスト

`npm run check` は、package.jsonに列挙したJavaScriptの構文を検査します。`npm test` は `tests/*.test.js` を実行します。

テストでは、キューの保存・連続操作・編集、Enterと送信ボタンの扱い、複数行入力、会話の切り替え、モデル・ツール選択、Deep Research・Canvas、回答・引用の表示などを確認します。

特定のテストだけを実行する場合は、次のように指定します。

```sh
node --test tests/queue-storage.test.js
node --test tests/queue-edit-intervention.test.js tests/research-canvas.test.js
```

JSDOMのテストでは、ログイン済みサービスの実際の応答や、ブラウザ上のすべての入力処理までは確認できません。

## Chromeでの手動確認

コードを変更したら、`chrome://extensions/` で拡張機能を再読み込みし、対象タブとQueue Managerも再読み込みします。検証用のチャットで、変更に関係する操作を確認してください。

| 確認する操作 | 期待する結果 |
| --- | --- |
| Enter・Shift+Enter・＋・Ctrl/Cmd+Enter | 通常送信・改行・キュー追加を使い分けられる |
| 管理画面・ポップアップでEnter | 対象タブへ直接送信し、キューへ追加しない。失敗時は入力を残す |
| 以前のEnter設定が保存されている状態 | 設定値に関係なくEnterは通常送信、Ctrl/Cmd+Enterはキュー追加になる |
| 日本語の変換確定 | IMEの変換確定だけで送信・追加しない |
| 生成中の手動送信・生成停止 | サービスが提供する途中介入・停止を使える |
| 複数件の追加・並び替え・削除 | 保存後の順序と件数が操作結果と一致する |
| 編集中の状態更新・保存・キャンセル | 下書きとカーソル位置を保持し、保存・破棄を使い分けられる |
| 一時停止して同じタブを再読み込み | キューと停止状態を復元する |
| Geminiを非表示にしてキューを実行 | 別タブを表示したまま入力・送信・状態同期が進み、タブを前面へ出さない |
| 複数行・空行・コードを含む一括追加 | 選択した区切り方に従って登録・送信する |
| `/newchat` とその後の質問 | 同じタブで会話を切り替え、残りの順序を保つ |
| アプリ・モデル・Research・Canvasの指定 | 実際のメニューで選択を確認して送信する |
| 利用できない指定 | プロンプトを保持して停止し、理由を表示する |
| Research計画の確認 | 開始操作を待ち、後続の質問を送信しない |
| Queue Managerとポップアップ | 対象タブのキュー・回答・状態を表示し、操作できる |
| 会話の上端へスクロール | 過去ログを取得し、取得済みのログと表示位置を保つ |
| 過去ログの取得失敗・タイムアウト | 「ログが取得できません」と表示し、再取得できる |
| スクロールバーの表示・ドラッグ | 表示幅を使わずに重ねて表示し、縦・横とも移動できる |

手動確認の記録には、サービス名、拡張機能のバージョン、確認した操作と結果を残します。アカウントやプランによって利用できない機能は、未確認として記録してください。

## 変更を提出する前に

構文検査と変更に関係するテストを実行し、必要な手動確認の結果を整理してください。READMEの操作方法や対応機能を変更した場合は、実装との一致も確認します。

検証した範囲と未確認の範囲を分けて記載し、プロンプト、回答、ログに個人情報や認証情報が含まれていないか確認してから共有してください。
